# 持ち主フロー(ログイン必要)

全体像は `docs/overview.md` を参照。

## フロー図

```
シール購入(EC / Amazon)
  ↓
ログイン → タグのアクティベーション(トークンと持ち物を紐付け)
  ↓
受取拠点(郵便局・営業所)を事前登録
  ↓
【待機】拾得の通知を待つ
  ↓
通知受信 → 届け方法・場所・メモ・写真を確認
  ↓
  ├─ どこかに届ける だった場合 → 場所へ受け取りに行く
  └─ 郵送 だった場合           → 局留めの保管期限内に受け取り(期限アラートあり)
  ↓
「受け取り確認」ボタン
  ↓
  ├─ 拾得者が受け取り先を登録済み → 「お礼」ページに送り先が表示され、持ち主が直接お礼を送る
  │                                (当サービスは送金を代行しない。自己申告で「送金済み」に更新)
  └─ 拾得者が匿名のまま           → お礼フローをスキップして完了
```

## 画面ごとの補足

### 事前準備
- シール購入後、ログインしてトークンと持ち物を紐付ける(アクティベーション)。実装詳細は `docs/token-security.md`
- 郵送に備えて受取拠点(郵便局名・住所・受取人名)を事前登録しておく。実装詳細は `docs/anonymous-mail.md`

### 通知確認
- 届け方法(どこかに届ける/郵送)・場所・メモ・写真を確認できる画面
- 郵送の場合は局留めの保管期限(`expires_at`、目安10日)が近づくとアラートを出す
- **通知手段はメールを主軸にする**(ウェブアプリ前提のため)
  - Android/Chromeでは Web Push(Firebase Cloud Messaging等)を追加の通知手段として使える
  - iOS Safariは Web Push対応が限定的・不安定なため、確実に届く手段としてメール(SendGrid/AWS SES等)を必須にし、プッシュ通知は「使えれば追加する」位置づけとする

### 受け取り確認・お礼
- 「受け取り確認」は持ち主の自己申告ベース(対面受け渡しの信頼性については `docs/open-issues.md` を参照)
- 受け取り確認をトリガーに、拾得者が受け取り先を登録済みなら「お礼」レコード(デフォルト1,000円)を作成
- **お礼の送金は当事者間で直接行う**。当サービスは資金を預からず、送金も代行しない
  (資金決済法上の為替取引に当たらないようにするため。`docs/legal-risks.md` B、
  将来の拡張案は `docs/payout-options.md` 参照)
  - 「お礼」ページに拾得者の送り先(受け取り方法・アカウント)を表示するだけ
  - 持ち主が自分の PayPay / デジタルギフト等で直接送り、「送金済みにする」で自己申告
- お礼は遺失物法上の報労金ではなく、持ち主から拾得者への任意の謝礼として扱う
- 拾得者が匿名のまま(受け取り先未登録)だった場合はお礼フローをスキップ

## 関連するAPI

- `POST /api/tags/activate` — タグと持ち物の紐付け
- `POST /api/owner-pickup-points` — 受取拠点の事前登録
- `POST /api/return-cases/:id/receive` — 受け取り確認
- `POST /api/rewards/:id/pay` — お礼を「送金済み」にする(持ち主の自己申告。実送金は行わない)

詳細は `docs/api.md` を参照。
